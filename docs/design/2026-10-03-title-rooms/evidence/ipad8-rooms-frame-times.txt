# §11.6, iPad 8 (A12, iPad11,6, iPadOS; the stage 1180x885 drawn into 2160x1620 at 60 Hz). The QA app
# (io.fol2.glassvow.qa, never the production bundle) built from the PR B head named on each block, with the
# QA-only bench patch applied for the export and reverted at once (evidence/pr-b-qa_rooms_patch.py.txt: it
# attaches tools/bench_rooms.gd's Bench node to Main when launched with --rooms-bench, and writes which
# licence files the pack holds). The batch (evidence/pr-b-device_batch.sh.txt) holds the shared iPad's lock
# from install to the last launch, checks before each launch that the installed QA app is the one it built,
# launches it with --rooms-bench --qa-nonce=<label>-<epoch> --locale=<code>, and keeps a launch's rows only
# when they carry that nonce and the label ipad8-<head>; the device is found by model at run time.
#
# A saved run's title, 30 s at rest; then each room's word tapped through the engine's own input path (a
# touch parsed in screen pixels), the room held (30 s at rest on its first opening, 3 s after) and its Return
# tapped: 10 laps a room. The first opening is the first since install (cold pipelines), reported apart.
# "tap->first moved": from the release to the draw of the tap frame, which already moves (the passage takes
# its first step in that frame's process step; a --fixed-fps 60 capture shows the veil darkening the stage
# by 6% on it). The bench parses the release in a frame's process step, so it waits out the rest of that
# frame (about 16 ms here, the present wait being inside the draw): the worst case for a finger.
# "tap frame": the wall interval of the frame the room is built on. "passage": every other frame of the
# arrivals and departures. On iOS a frame's work (process to its draw) includes the present wait, so it
# equals the wall interval and is not the comparable number here; the wall interval is. The title at rest
# is itself over 16.7 ms at P95 (vsync jitter), so the rooms at rest and the passages are read against it.
