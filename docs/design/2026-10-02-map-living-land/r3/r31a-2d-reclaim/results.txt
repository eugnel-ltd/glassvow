WHAT SHIPPED
- Film grain on the map: drawn by the map's display shader
  (presentation/map/map_display.gdshader, MapFilmGrain) as one fetch of a fixed
  256 px white-noise tile per display pixel, with the TransitionLayer grain's
  strength (0.05 overlay), whole-pixel jumps and rate (read from its
  constants), and none under Reduce Motion. Main keeps TransitionLayer's
  screen-reading grain off while the map shows; every other route turns it
  back on (unchanged). The map now has no screen-texture reader at all.
- Tilt-shift band at the stage's resolution: a view of its own
  (MapTiltShiftView, 2D only, the stage's size) runs the same 13-tap band
  shader texel for texel; the stage is its child, so the engine draws the
  stage first; the view renders only when the stage renders or the band
  moves. The display is a plain upscale plus the grain.
- set_focus_band no longer re-applies the band every frame (trace open
  issue 4): an unchanged band touches nothing.
- Shipped the stage-resolution band, not the static-haze-mask fallback: it
  reads identically in A/B crops (below) and it is cheaper (budget line).

R3.0 DEVICE CONDITIONS (is a GPU performance-state Device Condition on?)
- devicectl has no device-condition command or field (device info details,
  ddiServices; device/batch1-ctl-vs-head/device-details.txt).
- The Metal System Trace records the state in tables the CLI can export
  (tools/map_trace/display.py prints them): in all four traces today and in
  the trace spike's j-live trace, gpu-performance-state-info reads
  "consistent state available Yes, enabled No, sustained No, state 0", the
  driver's desired state is 0 throughout (gpu-performance-device-state-
  intervals), and the thermal state is Nominal with is-induced No. A GPU
  performance-state condition works by enabling that consistent state, so by
  this evidence none was on. The states themselves move (Minimum 12-95%,
  Medium 5-88%) as DVFS does. Instruments still labels every interval
  "induced ... due to active device conditions", which these fields
  contradict. Xcode's Devices window remains the authority if the owner
  wants to confirm.
