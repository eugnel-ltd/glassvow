# Maintained macOS component venue: feasibility

The current component is Linux software-Vulkan evidence. Job `117746266505`
completed the supported RGBA8 transports, but ASTC was unavailable and the
strict verifier rejected a missing script cache. A desktop Metal venue may
provide the missing compressed-format component proof; it cannot establish
iOS template, physical A12, memory, timing or release acceptance.

On 18 October 2026, GitHub's [standard public runner inventory](https://github.com/github/docs/blob/main/data/reusables/actions/supported-github-runners.md)
lists arm64 `macos-14`, `macos-15` and `macos-26` and states that standard
public-repository runners are free and unlimited. The [arm64 limitations](https://github.com/github/docs/blob/main/data/reusables/actions/macos-runner-limitations.md)
and [macOS 15 image inventory](https://github.com/actions/runner-images/blob/main/images/macos/macos-15-arm64-Readme.md)
establish a supported host/toolchain option. They do not establish an exposed
Metal GPU or ASTC/ETC2/EAC format support. No macOS component workflow or GPU
result exists in this delivery.

Any venue qualification belongs in the maintained native component pipeline,
with the existing exact source/archive, ordered patch, observer, executable
and fixture identities. Its first bounded phase must record the actual host,
architecture, selected Xcode/compiler, an exposed Metal device
(`MTLCreateSystemDefaultDevice`), and the required compressed formats for the
probe's sampling/update/copy uses. A runner label or Apple CPU is insufficient.
Stop before the full paired native build if the device or required formats
are unavailable; retain an explicit unqualified result. Do not select a paid
runner, spoof support, decompress as fallback, or repeatedly rerun the same
incapable venue.

If capability is established, run the complete existing case matrix on fresh
baseline and candidate engines with matching platform flags. Record actual
requested/created/native formats, backend row pitch and alignment, every
request/copy/barrier/wait, and exact GPU readback bytes. The Linux wrapper's
Xvfb/lavapipe and banner checks need an explicit Metal component counterpart;
silencing those checks would not qualify a new backend. The standalone empty
global-class cache and strict native ERROR rejection remain required.

The separately selected owner-Mac/Grok-tailnet route remains a governed
physical-machine fallback under `docs/agents/cloud-environment.md`. Its
current reachability, device capabilities and shared lock must be established
through the existing handoff. This note starts no job, changes no workflow,
claims no GPU capability, and changes no shipping template or acceptance bar.
